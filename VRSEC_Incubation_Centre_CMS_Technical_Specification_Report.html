2.6 Stock Decrement and Increment Engine

  • On Issue (issueComponents()): Validates stock availability. Decrements availableQuantity = availableQuantity - quantity and increments issuedQuantity = issuedQuantity + quantity. Serial barcode/QR tags are set to status = 'issued'. A row is inserted into public.issued_components.
  • On Return (returnComponents()): Validates return count $le$ unreturned count. Increments availableQuantity = availableQuantity + returnQty and decrements issuedQuantity = max(0, issuedQuantity - returnQty). Serial tags are reset to status = 'available'. Updates public.issued_components to 'returned' and resolves any corresponding record in public.overdue_components.

4. Integration Architecture with Hardware / ESP32 / Python Layer

  • Physical Setup & Port Binding: ESP32 Dev Module connected via USB Serial on COM4 at 115200 baud. Handled by hardware/vision/esp32_relay_bridge.py.
  • Relay Pinouts (Active-HIGH Logic):
    • Relay 1: Connected to GPIO 22 $ ightarrow$ Controls Light 1 (Zone Z1).
    • Relay 2: Connected to GPIO 23 $ ightarrow$ Controls Light 2 (Zone Z9 / Z2).
  • PZEM-004T v3.0 Energy Telemetry:
    • Connected to ESP32 Hardware UART2 (GPIO 25 = RX $leftarrow$ PZEM TX, GPIO 33 = TX $ ightarrow$ PZEM RX).
    • Measures AC Voltage, Current, Power (W), Cumulative Energy (kWh), Frequency (Hz), and Power Factor. Emits structured telemetry over Serial.
  • 3x3 Zoning Topology & Gesture Arbitration:
    • Grid zones: Z1 (Physical GPIO 22), Z9 (Physical GPIO 23), and Z2-Z8 (Simulated / mapped).
    • 10.0-second non-blocking vacancy timer per zone. Occupancy triggers relay ON; vacancy timer expiration resets relay to OFF.
    • Hand gestures: Palm-facing gesture forces Fan OFF; Back-of-hand gesture forces Light OFF with a 5-frame stability threshold.
    • Telemetry from Python vision service is polled by ZoneGestureService.js, updating UI and logging into PostgreSQL public.power_consumption.

5. Authentication & Face/Biometric Module Status

Implementation Status: The biometric face recognition module is fully implemented and verified in the codebase, operating via a local Python FastAPI microservice on port 8001.
  • Role-Based Access Control (RBAC):
    • Admin: Unrestricted access to all modules, plain student passwords, and retention plans.
    • Staff: Desk access only (Issue, Return, Overdue, Lab Entry/Exit, Students Inside, Projects). Administrative tabs are restricted.
    • Student: Personal portal only (borrowed items, personal attendance, project showcase submission).
  • Biometric Engine (InsightFace buffalo_l): Generates 512-dimensional facial embedding vectors. Raw images are processed in RAM and discarded immediately. Embeddings are stored in SQLite (attendance.db).
  • 10-Pose Head-Pose Guide (FaceRegistrationModal.jsx): Guides students through Frontal, Yaw Left ($>15^circ$), Yaw Right ($>15^circ$), Pitch Up ($>10^circ$), and Pitch Down ($>10^circ$) to build an accurate multi-angle profile.
  • Kiosk Attendance Terminal (FaceAttendance.jsx): Live webcam feed matched against registered embeddings. Cosine similarity $ge 0.65$ records automatic lab entry/exit with duration calculation.

        ├── Query: SELECT * FROM public.issued_components WHERE status != 'returned'
        ├── Filter: Check each component: is (CURRENT_DATE > item.dueDate)?
