3 Current Technical Architecture

The application architecture comprises three tightly decoupled tiers designed for high resilience and zero single-point-of-failure:

1. Frontend Client Layer (React 19 + Vite)

  • UI Layer: Single Page Application with 22 modular views, role-based conditional routing, and Lucide React icons.
  • Reactive State: In-memory memoryStore provides synchronous sub-millisecond reads for all UI components.
  • Dual Persistence: Synchronous localStorage and asynchronous IndexedDB (IncubationCMS_DB v2) maintain offline availability.
  • Sync Manager: SyncService maintains an exponential backoff mutation queue and RPC idempotency ledgers.

2. Local Laboratory Edge Environment

  • Device Gateway: Node.js gateway (port 5050) protected with Windows DPAPI machine keys and replay nonces.
  • ESP32 Relay Controller: C++ firmware (192.168.4.101) with mbedTLS HMAC-SHA256 hardware attestation.
  • Face Attendance Station: Local FastAPI server (port 8001) running InsightFace on local lab PC.

3. Production Cloud Infrastructure

  • Cloudflare Pages: Global CDN hosting static application shell with SPA fallback (_redirects).
  • Cloudflare Functions: 5 serverless API handlers (/api/*) with CORS origin whitelisting.
  • Supabase Auth: Cryptographic JWT authentication, session refresh, and role claim injection.
  • Supabase PostgreSQL: 24 relational tables, 17 RPCs/triggers, and strict Row Level Security (RLS).

6 Offline Functionality & Synchronization Report

  • Which operations work offline? Lab Entry/Exit recording, component issuing and returns (with local inventory deduction and physical tag verification), project creation, expenditure logging, reflection book entries, and Excel report generation.
  • Which operations require Supabase online access? Initial user credential verification when signing in for the first time, server-side student registration (register-student.js), and concurrent multi-terminal inventory synchronization.
  • Offline Mutation Queue: Handled by SyncService via enqueueMutation(). Each mutation receives a unique mutationId and mandatory p_operation_id for atomic RPCs.
  • Conflict Resolution: Timestamp comparison against cloud updated_at (last-write-wins).
  • Ledger Idempotency: Supabase table public.processed_rpc_operations caches executed RPC responses, preventing duplicate stock deductions on mutation replay.
  • Corruption Fail-Safe: Corrupted JSON in localStorage is trapped safely, leaving stored mutation queues intact.
